# Decisions

One line per decision: what was chosen and why. Newest at the bottom. When a decision is
reversed, add a new line that says so; do not rewrite history.

| # | Date | Chunk | Decision | Why |
| --- | --- | --- | --- | --- |
| 1 | 2026-11-11 | C0 | TypeScript is pinned to 6.0.x, not 7. | typescript-eslint 8 supports TypeScript below 6.1 only; type-aware linting matters more than the newest compiler. |
| 2 | 2026-11-11 | C0 | Internal packages export TypeScript source; there is no build step and Next.js transpiles them. | One less thing to keep in sync across 20 packages; typecheck, lint and tests work on source directly. |
| 3 | 2026-11-11 | C0 | One root ESLint flat config with type-aware rules; packages run `eslint .` and have no config of their own. | A single place for rules; no drift between packages built by different sessions. |
| 4 | 2026-11-11 | C0 | `strict`, `noUncheckedIndexedAccess`, `noImplicitOverride`, `noImplicitReturns` are on; `exactOptionalPropertyTypes` is off. | The last one fights types inferred by Zod and Drizzle and most vendor SDKs; the others catch real bugs cheaply. |
| 5 | 2026-11-11 | C0 | Every later chunk gets a pre-created package, and allowed dependencies between packages are a checked list (`tooling/boundaries.mjs`, part of `pnpm verify`). | Independent sessions cannot create import cycles or reach across layers by accident. |
| 6 | 2026-11-11 | C0 | The cross-chunk contracts are code in `@repo/core` (types plus Zod schemas, with tests), not only prose. | Later chunks compile against them; a mismatch is a type error instead of a late surprise. |
| 7 | 2026-11-11 | C0 | Entity ids are branded UUID types (`BusinessId`, `ConversationId`, ...). | Passing the wrong id is the classic cross-tenant bug; the compiler now refuses it. |
| 8 | 2026-11-11 | C0 | Events are named `entity.event` with a dot (`lead.qualified`, `message.received`). | Matches the names in the spec exactly; one convention for all events. |
| 9 | 2026-11-11 | C0 | The routing decision reaches the model as the tool result of `update_lead_fields` within the same turn, instead of a separate extraction call before the reply. | The reply must follow the decision; this needs one model round trip and keeps scoring deterministic code. |
| 10 | 2026-11-11 | C0 | Conversation history is replayed to Claude as plain text; thinking blocks are kept only inside one turn's tool loop. | On claude-fable-5-2 a replayed thinking block is rejected if the system prompt, tools or earlier turns changed, and admins can edit prompts, playbooks and knowledge mid-conversation. |
| 11 | 2026-11-11 | C0 | No Redis and no vector database in production. Counters, locks and rate limits use Postgres; knowledge retrieval uses Postgres full-text search. | Neither is in the decided stack; per-business knowledge is small; fewer vendors to operate. (pgvector is also not installed in the build VM.) |
| 12 | 2026-11-11 | C0 | Environment variables are declared once in `packages/core/src/env/spec.ts`; `.env.example` is generated from it and ESLint forbids `process.env` elsewhere. | Makes "keep .env.example current" mechanical: an undeclared variable cannot be read. |
| 13 | 2026-11-11 | C0 | Debounce = Inngest's static debounce plus a per-business sleep and a latest-message check; ordering = Inngest concurrency plus a turn lease in Postgres. | Inngest's debounce period cannot vary per business, and its concurrency limit applies to steps, not whole runs. |
| 14 | 2026-11-11 | C0 | Prettier formats code and config but not Markdown. | Docs are written by many sessions; reflowing tables and prose creates noise and failed checks. |
| 15 | 2026-11-11 | C0 | Turborepo runs with `envMode: "loose"` and never caches the `test` task. | Tests must see `ANTHROPIC_API_KEY`, `TEST_DATABASE_URL` and friends, and a cached pass could hide a broken database or service. |
| 16 | 2026-11-11 | C0 | Local and CI databases are plain PostgreSQL 16 with a role shaped like Supabase's `postgres` role (not superuser, bypasses RLS); C1 adds a Supabase-compatibility bootstrap. The Supabase CLI stack is not used. | PostgreSQL 16 is installed in the VM; the Supabase stack needs many container images and is slower to start. |
| 17 | 2026-11-11 | C0 | Playwright end-to-end tests run with `pnpm e2e`, outside `pnpm verify`. | They need browsers and a running app; `pnpm verify` stays fast and dependable as the gate for every chunk. |
| 18 | 2026-11-11 | C0 | Channels that notify rather than deliver (Gmail push, Graph, IMAP) and the widget call the pipeline's `ingest()` with normalized messages instead of implementing `parseWebhook`. | Their webhook body does not contain the message; fetching needs tenant credentials and belongs in a job. |
| 19 | 2026-11-11 | C0 | Alert email goes through a plain SMTP server (`ALERT_SMTP_URL`), and alert WhatsApp messages through the agency's own Cloud API number. | No extra email vendor; reuses the Meta module. C13 may revise. |
| 20 | 2026-11-11 | C0 | Refusals from the model (`stop_reason: "refusal"`) hand the conversation to a human, and server-side fallbacks are enabled by default behind a setting. | A support bot must never stall silently; a false-positive safety refusal should still produce an answer. |
| 21 | 2026-11-11 | C0 | Dependency versions in the pnpm catalog are the latest published on 2026-11-11 (Next.js 16.4, React 19.3, Zod 4.6, Vitest 5.1, ESLint 10, Inngest 4, Anthropic SDK 1.8, Drizzle 0.45). Only the ones C0 uses were installed and proven. | Start current; a chunk that finds an incompatibility changes the catalog and adds a line here. |
| 22 | 2026-11-11 | C1 | The system context is enforced by PostgreSQL, not by convention: `forBusiness()` / `forAgency()` run as the role `app_system`, which row-level security confines to the tenant held in transaction-local settings. This replaces "a connection that bypasses RLS plus repositories that add the predicate" in ARCHITECTURE §3 (corrected there). | A job query that forgets `business_id` then cannot cross tenants, so later chunks can use the full query builder safely instead of a restricted repository API. Costs one extra round trip per transaction. |
| 23 | 2026-11-11 | C1 | Cross-tenant code (webhook account → tenant, API key → agency, tenant lists for crons, create an agency) lives only in `packages/db` (`directory`, `platform`); no unrestricted client is exported. | Keeps every query that runs outside RLS in one reviewed place. |
| 24 | 2026-11-11 | C1 | Policies are declared in the Drizzle schema next to each table (`businessPolicies`, `sharedPolicies`, `agencyPolicies`) and generated into migrations; helper functions, triggers and the privilege sync are hand-written migrations (0000, 0002). | One place to read what a table allows; drizzle-kit cannot express functions, triggers or FORCE ROW LEVEL SECURITY. |
| 25 | 2026-11-11 | C1 | After every migrate, `app.sync_table_privileges()` forces RLS on every table and grants `authenticated` and `app_system` exactly the commands their policies cover; `anon` gets nothing. Migrations are applied only with `pnpm db:migrate`, never `drizzle-kit migrate` or `push`. | Supabase grants ALL on new tables to anon and authenticated by default; a table added without policies must be unreachable, not open. |
| 26 | 2026-11-11 | C1 | Signed-in users never write pipeline-owned tables (conversations, messages, leads, jobs, alerts, model calls...) nor channel and integration connections; client users are read-only everywhere. Such writes are server functions that check the role and then use the system context. | Sequence numbers, leases and statuses must not be editable through Supabase's REST API with a user's token, and `(channel, external_account_id)` maps webhooks to a tenant: a user who could write it could claim another agency's account. Fine-grained client permissions are settings, checked in server code. |
| 27 | 2026-11-11 | C1 | The switch for client logins is the column `businesses.client_portal_enabled`, not a settings row. | Row-level security has to read it on every query; settings are JSON owned by C2. C2 may declare a setting that drives the column. |
| 28 | 2026-11-11 | C1 | Encrypted credentials live in separate tables (`channel_connection_secrets`, `integration_connection_secrets`) with no policy for signed-in users, one encrypted JSON document per connection. | Not even the ciphertext can reach a browser through a user-context query or Supabase's REST API. |
| 29 | 2026-11-11 | C1 | Every foreign key between tenant tables is composite and includes `business_id` (or `agency_id` for agency-level parents). Rows that point at a parent are deleted with it; channel and integration connections are switched off (`revoked`, `disabled`) rather than deleted while conversations or bookings refer to them. | A row can then never reference another tenant's row, whatever the application does. Avoids `ON DELETE SET NULL` on composite keys, which needs PostgreSQL 15 column lists that Drizzle cannot express. |
| 30 | 2026-11-11 | C1 | Segments and playbooks belong to an agency (`agency_id`), not to the whole installation. | An agency's playbooks and segment settings must be invisible to any other agency. |
| 31 | 2026-11-11 | C1 | Closed vocabularies are `text` columns with CHECK constraints generated from the constant arrays in `@repo/core` and `packages/db/src/schema/vocab.ts`, not PostgreSQL enums. Timestamps are read as `Date`. | Adding a value is a generated migration; removing one is possible at all. Contracts use ISO strings, converted at the boundary. |
| 32 | 2026-11-11 | C1 | Sign-in sits behind an `AuthProvider` interface with two implementations: Supabase Auth, and a local provider (users in the compatibility `auth.users` table, HMAC-signed session cookie) enabled by `LOCAL_AUTH_SECRET` and never on Vercel. | There is no Supabase Auth server in the build VM or CI; the app, the seed users and later Playwright tests must be able to sign in. Realtime has no local equivalent: C8 and C16 need a fallback (polling) when Supabase is not configured. |
| 33 | 2026-11-11 | C1 | Sign-in, magic-link and sign-out are plain form posts to route handlers (`/auth/*`) with an origin check, not server actions; every outcome is a redirect to a path on this site with a short code. | They work without JavaScript, are testable as functions from Request to Response, and nothing a person typed ends up in a URL or a log. |
| 34 | 2026-11-11 | C1 | Magic links never create users (`shouldCreateUser: false`) and the form answers the same for unknown addresses. A user who authenticates but is a member of nothing is signed out again. | Accounts are created by the agency; the form must not reveal who has one. |
| 35 | 2026-11-11 | C1 | API keys are `hsrb_<8 hex>_<43 chars>`, stored as a SHA-256 hash and shown once. | A fast hash is sufficient for 256 random bits and keeps the import API's authentication to one indexed lookup. |
| 36 | 2026-11-11 | C1 | Test databases: each test file clones a migrated template database (`<base>_tpl_<hash of migrations>`); the helper starts local PostgreSQL when it is down and fails with the reason when it cannot. | Parallel test files and packages do not see each other, and a file pays about 0.1 s instead of a full migration. |
| 37 | 2026-11-11 | C1 | `apps/web/next.config.ts` loads the repository-root `.env.local`, and the `pnpm db:*` scripts load the same file. | `.env.example` sits at the root; Next.js only reads env files next to the app. |
| 38 | 2026-11-11 | C1 | Tenant-scoped object storage (`@repo/db/storage`: path convention, tenant guard, Supabase Storage client, local folder with signed URLs, memory store) is built in C1, with a small app route that serves the local store. | BUILD_PLAN has C8 building on "Storage from C1", and C3 needs it first (attachment download); the tenant path check is a security boundary and belongs with the data layer. |
| 39 | 2026-11-11 | C1 | New environment variables: `DATABASE_POOL_MAX`, `LOCAL_AUTH_SECRET`, `SEED_USER_PASSWORD`. | Pool size is infrastructure tuning; the other two exist only for local sign-in and for seeding a hosted development project without a password written in the repository. |
