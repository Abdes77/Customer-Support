# C16 plan: inbox, leads and analytics

Goal: fill the slots C15 left in `apps/web` with the operational screens, on the services of
C8 to C14, with authorization decided on the server for every page, action and route.

## Slices (each ends with `pnpm verify` green)

1. **Inbox and conversation.** `packages/db/src/repositories/inbox.ts`: reads as the signed-in
   user (row-level security decides): the inbox list (filters: business, channel, open or
   closed, unread, assigned to me or nobody, taken over, search over names, phone, email and
   message text), one conversation with its messages, attachments, lead (criteria, score,
   report, routing history), takeover lock, bookings, and staff-only internal notes. Writes
   that touch pipeline tables (mark read, assign) are system-scope functions called after the
   role check; notes are written as the user (RLS: staff, under their own name).
   `@repo/handoff` gains: `takeOver` claims a lock that no person holds (rule, provider inbox);
   `sendManualReply` with `requireHolder` (only the person holding the takeover may reply) and
   an idempotency key; `enqueueHumanMessage` in `@repo/pipeline` stores the key and returns
   the first message for a repeated key (exactly once). Pages `/inbox` and `/inbox/[id]`,
   server actions, an attachment route that serves files only to people who may see the
   conversation (safe type, `nosniff`, `attachment` unless an image), live updates through
   Supabase Realtime when configured (migration adds the tables to `supabase_realtime` when
   that publication exists) and polling otherwise (`router.refresh()`).
2. **Connection pages.** `/businesses/[id]/channels`: website chat (`widgetEmbedInfo`, set up,
   rotate, on/off), WhatsApp (`getWhatsApp()`: numbers, Embedded Signup through Meta's SDK,
   templates, disconnect), Messenger and Instagram (`getMetaPages()`: Facebook Login with the
   `choose_page` step, disconnect), email (`getEmail()`: Gmail and Microsoft OAuth start,
   IMAP/SMTP form, sync now, disconnect). `/businesses/[id]/integrations`: calendars and
   Calendly (`getScheduling()`), CRMs (`getIntegrations()`: connect by OAuth or keys, options,
   test, mapping with preview, deliveries with retry, disconnect), webhooks (targets, test,
   secrets revealed or rotated by agency admins only), a link to alert contacts. Each shows
   the stored state only: not set up on this deployment, not connected, connected, needs
   reconnecting, error with the stored reason. Action bodies take their services as
   parameters so tests run them against the fakes of C9 to C14.
3. **Leads, analytics, audit, client portal.** Lead list (filters: business, status, band,
   routing, channel, search, date) and CSV export (same filters, same authorization, cells
   starting with `=`, `+`, `-`, `@`, tab or CR neutralized). Analytics from stored rows as the
   user: conversations, first-response time (median and mean of the first outbound after the
   first inbound), qualification rate, booked meetings, drop-off step (furthest step reached:
   wrote once, replied to the bot, qualified, booked), by business, channel and segment. The
   seed gains two website-chat conversations so channel breakdown and drop-off are provable;
   a test checks the totals against the seed. Audit log viewer for agency admins (RLS reads
   it for admins only) with sensitive values masked. Client portal: one function decides,
   per business and role, from `client_portal.*`: see conversations, take over and reply,
   see leads, see reports, export, see analytics; staff always; notes, escalations, alerts,
   assignment and connections are staff only.
4. **Browser tests and docs.** `e2e/inbox.spec.ts` (takeover and manual reply on the test
   channel, release, notes), `e2e/connections.spec.ts` (every connection page in each state),
   `e2e/portal.spec.ts` (client user: own business only, swapped ids are "not found", what
   the settings allow), analytics totals in the browser. Screenshots at 1280×800 and 390×844.
   Docs: ARCHITECTURE "As built (C16)", BUILD_PLAN, DECISIONS, HUMAN_TODO (live Realtime
   check), report.
