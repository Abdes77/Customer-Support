# C6 plan: industry playbooks and business knowledge

Goal: `packages/knowledge` generates, versions and serves one industry playbook per segment,
and imports, stores and retrieves the facts of each business. The pipeline's placeholder
retriever and playbook loader (C4) are replaced by this package's.

Sources checked before building: the Claude API reference bundled with the build tools
(cached 2026-11-03) and the live pages for the web search tool and for server tools
(`pause_turn`, mixing server and client tools) on platform.claude.com, reachable from the VM
on 2026-11-12. There is no `ANTHROPIC_API_KEY` in the VM, so generation is proven against a
scripted model and the live run is recorded in `docs/HUMAN_TODO.md`.

## Playbooks

1. **Document (`@repo/core`, `src/playbooks/document.ts`).** The v0 contract stays, with two
   changes: every text has a length limit, and a price norm is numbers (`lowUsd`, `highUsd`,
   `unit`, `region`, `notes`) instead of a free-text range. Two levels of checking: the
   schema (every save) and completeness (minimum content per section, at least three
   sources, dollar figures only in the price norms; required for a generated document,
   reported as warnings for a hand edit).
2. **Generation (`src/playbooks/generate.ts`).** One append-only conversation with the model
   from `model.playbook.*`: three research steps with the web search tool (direct calls,
   `max_uses` from a setting, `pause_turn` resumed), then one call that must end in the
   strict client tool `submit_playbook`. The submitted document is validated; problems go
   back as the tool result (at most two repairs). Sources must be pages the search returned:
   URLs are collected from the search-result blocks and citations of every response, and a
   source that was never returned is refused. Every model call is one job step and one
   `model_calls` row. Without a key on a developer machine a built-in starter playbook is
   stored instead (origin `starter`); a hosted deployment without a key fails the run.
3. **Versions (`src/playbooks/store.ts`).** Stored versions never change: a database trigger
   refuses any update except the `is_active` flag (C1 review). An edit, a generation and a
   rollback each insert a new version and activate it, under a per-segment advisory lock and
   an optional `baseVersion` check. Diff is a pure function over two documents.
4. **Reuse.** `assignSegment()` finds or creates the segment by slug, puts the business in
   it, applies the segment preset from C2 the first time, and asks for a playbook: an active
   version is reused, an open run is joined, otherwise a `playbook_generations` row is
   created and `playbook.generation_requested` emitted (job `knowledge-playbook-generate`).
5. **Overrides (`src/playbooks/overrides.ts`).** A business replaces whole sections
   (`business_playbook_overrides`); the loader the pipeline uses merges them and ignores a
   stored override that does not validate.
6. **Prices.** The engine shows the price norms to the model only when `pricing.disclosure`
   is not `never` and `pricing.use_playbook_ranges` is on; the output guard allows exactly
   those figures under exactly that condition (one shared predicate).

## Business knowledge

1. **Items (`src/knowledge/items.ts`).** List (with a stale flag from
   `knowledge.stale_after_days`), create, update, archive, restore, delete, reorder, pin.
   Every item has a source and its last-updated time.
2. **Import (`src/import`).** A hand-written RFC 4180 parser; a mapping from columns to
   business profile fields and fact categories (wide format) or to category, title and
   content columns (long format), with a suggested mapping from the headers; row-level
   validation with errors that name row and column. Facts are upserted by a stable import
   key, so importing again updates instead of duplicating; a fact edited by hand is never
   overwritten. Every import is an `import_runs` row. The same code serves the CSV upload
   and the JSON API.
3. **API (`apps/web/src/app/api/v1`).** `POST /api/v1/knowledge/import` (JSON) and
   `/import/csv`, `GET /api/v1/knowledge/imports/{id}`; bearer API key (C1), scope
   `knowledge:write`, a key bound to a business can only write that business.
4. **Website (`src/crawl`).** One fetcher guarded against server-side request forgery: http
   and https only, no credentials, default ports, DNS resolved once and the connection
   pinned to the checked address, private, loopback, link-local and reserved ranges refused,
   every redirect checked again, size, time and content-type limits. The crawler stays on
   the business's own host, honours robots.txt and `knowledge.crawl_max_pages`. Facts are
   extracted by the model (`model.knowledge_extraction.*`) from page text placed as data,
   and a fact is kept only when its quote is found on the page. Job `knowledge-import`.
5. **Retrieval (`src/knowledge/retriever.ts`).** Core facts in a stable order; per-message
   look-up by PostgreSQL full-text search plus the categories a message asks about
   (financing, warranty, licence...), imported and hand-written facts before website facts.

## Order of work

Contracts and events, migration and isolation matrix, settings, engine wiring, playbooks,
knowledge, import API, composition, docs and report.
