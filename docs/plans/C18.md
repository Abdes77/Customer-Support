# C18 plan: end-to-end tests and launch preparation

1. **Monitoring gap (THREAT_MODEL 4.16).** A readiness check that does not depend on the job
   runner: count customer messages that no turn dealt with for 30 minutes to two hours
   (`countUnansweredMessages` in `packages/pipeline`), fail `/api/health/ready` when there are
   any. Database test plus readiness test.
2. **Load test.** `pnpm load:test`: 50 businesses, three conversations each, two bursts of
   three messages, through the real pipeline (test channel, real engine with the offline
   model, local PostgreSQL, in-process jobs, real debounce and reply wait). Checks one reply
   turn per burst, order, latency beyond the configured wait, no limit at defaults, and one
   business at its daily reply cap (one notice per stopped conversation, an emergency still
   answered). Throwaway database only; refuses anything but a local server. A small version
   runs in `pnpm verify` so the command does not rot.
3. **Browser journeys on every local channel.** Development-only switches (ignored on a
   deployment) point the Graph API at a fake on this machine and let IMAP/SMTP inboxes use a
   local mail server. The e2e server starts both and a third business with WhatsApp,
   Messenger and Instagram connected. Specs: WhatsApp (burst, duplicate, qualification,
   statuses, forged signature, takeover reply), Messenger and Instagram (qualification, Page
   token, takeover reply on the same platform), email (connect from the admin panel, threaded
   replies), the test channel (qualification, report, lead list, CSV).
4. **Docs.** `docs/RUNBOOK.md`, `docs/ONBOARDING.md`, `docs/META_APP_REVIEW.md`, the rewrite of
   `docs/HUMAN_TODO.md` as one ordered checklist (every live check, variable and command kept;
   every reference to an entry number updated), `docs/BUILD_REPORT.md`, ARCHITECTURE,
   BUILD_PLAN, THREAT_MODEL (4.16, 4.9), DECISIONS, CLAUDE.md.
5. **Checks.** `pnpm verify` uncached, `pnpm e2e -- --trace off`, `pnpm eval --mode mock` (no
   change to packages/ai, but cheap to confirm), the full load test.
6. **People management (follow-up attempt).** Close BUILD_REPORT open item 8: a People page for
   the agency and a People tab per business; actions as functions of the session
   (`apps/web/src/server/people`) with the invitation path behind an `Inviter` (Supabase admin
   API with a fake in tests; local sign-in shows the link); least-privilege roles with an
   off-by-default setting for owners managing staff; migration 0016 (no writes to one's own
   membership, last agency admin kept by a locking trigger, audit index for the 20-a-day
   limit); database tests of direct writes as every role, action tests as every role across
   tenants, the browser test (admin adds a client owner, they sign in, see one business, are
   turned away after removal); THREAT_MODEL 2.12, docs, checks again.
