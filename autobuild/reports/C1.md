## Decisions that differ from the C0 documents (all in docs/DECISIONS.md)

- **The system context does not bypass row-level security.** `forBusiness()` and
  `forAgency()` run as a role that PostgreSQL confines to the entered tenant, so later
  chunks get a full Drizzle transaction instead of a fixed set of repositories, and a query
  that forgets `business_id` still cannot cross tenants.
- **Signed-in users are read-only on pipeline tables and on channel and integration
  connections**, and client users are read-only everywhere. Those writes are server
  functions that check the role and use the system scope. The connection rule exists
  because `(channel, external_account_id)` maps a webhook to a tenant.
- **Credentials sit in separate tables** that no user can read, not in a column of the
  connection row.
- **A local sign-in provider** stands in for Supabase Auth in development and CI.
- **Object storage was added to this chunk** because BUILD_PLAN has C8 building on "Storage
  from C1".

## Found and fixed along the way

- After `db:reset` recreated schema public, the restricted roles could not see any table:
  everything had relied on the grant to PUBLIC that only a stock schema has. The privilege
  sync now grants schema usage itself, the doctor checks it, and the migration test revokes
  the PUBLIC grant before migrating.
- `import.meta.dirname` is undefined inside the Next.js server bundle, which broke the build
  as soon as a route imported the storage module. The local storage folder is now found
  from the working directory.
- A raw `Date` inside a Drizzle `sql` template fails with this driver. Documented in
  ARCHITECTURE §8 (use column operators, or an ISO string with a cast).
