## What was built

- **`@repo/channel-meta`** (shared with C10): webhook handshake and `X-Hub-Signature-256` over
  the raw body with constant-time comparison; a Graph client (injected `fetch`, token only in
  the header, `GraphApiError` carrying Meta's code); `classifyGraphError` (131047 window closed,
  rate limits with waits from the code or `x-business-use-case-usage`, transient and auth
  codes); media download (Meta hosts only, redirects checked hop by hop, size caps) and
  upload; the Embedded Signup code exchange.
- **`@repo/channel-whatsapp`** adapter: every inbound type (text, image, video, document,
  sticker, audio/voice, location, button and list replies, template quick-reply buttons,
  reactions added/removed, contact cards, unsupported; system notices skipped), statuses with
  errors, coexistence echoes as `human_agent_replied`, template/account/quality updates as the
  new `provider_event` signal. Sends text (no link previews), reply buttons (≤3 × 20 chars) or
  lists (≤10 rows), media uploaded from our storage, templates (named or positional), read
  receipts, typing indicator, media download by id. Customer identity: BSUID, else phone.
- **`@repo/channel-whatsapp/server`**: Embedded Signup completion (exchange, proof that the
  number is in the WABA, subscribe, register with a random PIN kept encrypted with the token,
  store; a number of another business is refused before any Meta call), connection list and
  disconnect for C16, templates (create with named parameters from a fixed list, sync,
  delete, status webhooks), the window fallback, the account-event handler, the voice-message
  enricher with a Deepgram transcriber, the `whatsapp-template-sync` cron, and the live check
  script.
- **Pipeline** (`packages/pipeline`): the template fallback outside the 24-hour window (and
  once more when Meta answers 131047), recorded on the message; the three delivery-status gaps
  from the C3 review fixed (`message_parts`, `pending_delivery_statuses`, migration 0009,
  advisory lock per provider id, sweeper cleanup); new extension points `windowFallbacks`,
  `providerEvents`, `attachmentEnrichers`; typing on the newest customer message; quick
  replies written as text when `channels.whatsapp.buttons` / `channels.meta.quick_replies`
  is off; webhook bodies up to 4 MB.
- **Shared changes**: `contracts/channel.ts` (additive: `provider_event`, `namedVariables`,
  `WindowFallbackResolver`); `directory.findChannelConnectionsByBusinessAccount` with an
  expression index; isolation matrix entries for the two new tables; setting
  `channels.whatsapp.staff_reply_template` (SETTINGS.md regenerated); env
  `DEEPGRAM_API_KEY`, `META_TEST_WHATSAPP_BUSINESS_ACCOUNT_ID`, `META_GRAPH_API_VERSION`
  default `v27.0` (`.env.example` regenerated).
- **apps/web**: adapter, fallback, event handler, enricher and cron registered in
  `src/server/pipeline` when `META_APP_SECRET` and `META_WEBHOOK_VERIFY_TOKEN` are set;
  `POST /api/oauth/meta/whatsapp` (agency staff, same-origin JSON); `getWhatsApp()`.
