## The carried-over notes

1. **C4 placeholders.** Replaced. `defaultPlaybookLoader` and the placeholder retriever over
   `knowledge_items` are gone from `packages/pipeline`; only `emptyKnowledgeRetriever` (for
   tests) remains. Proof: `composition.db.test.ts` "gives the engine the segment's playbook
   with the business's own sections, and price norms only as the pricing settings allow" and
   "gives the engine the facts of the business and nobody else's".
2. **`applySegmentPreset`.** Called by `assignSegment` the first time a segment is served
   (the segment was created now, or no other business is in it), not for later businesses, so
   a value an admin reset stays reset (DECISIONS 108, test in item 3).
3. **Immutable versions (C1 review).** Made immutable in the database, not only in code
   (DECISIONS 103, `packages/db/drizzle/0006_playbook_version_guard.sql`): an `AFTER UPDATE`
   trigger refuses every change to a stored version except `is_active`; signed-in users have
   no delete policy; a `BEFORE INSERT` trigger records the signed-in user as the author. An
   edit, a rollback and a regeneration each create a new version. It holds for the system
   scope and the unrestricted connection too:
   ```
    ✓ playbook versions are immutable > lets staff add a version and flip the active flag, and nothing else
    ✓ playbook versions are immutable > holds on the system scope and on the unrestricted connection too
    ✓ playbook versions are immutable > no signed-in user deletes a version; versions go with their segment
    ✓ versions > an edit is a new version; the old one is untouched; diff and rollback work
    ✓ versions > keeps version numbers gap-free and one version active under concurrent saves
   ```
4. **Price norms and the output guard (C4 review).** A playbook's price norms reach the model
   only when `pricing.disclosure` is not `never` and `pricing.use_playbook_ranges` is on
   (both default to not showing them), and the guard's allowed amounts are computed by the
   same function from the same norms, so the two cannot drift (DECISIONS 102). No other
   section of a playbook may contain a dollar figure: refused on every save, for overrides
   too. `RENDER_VERSION` is 2.
   ```
    ✓ price norms in the playbook section > are not shown under the default settings
    ✓ price norms in the playbook section > are not shown when prices are never disclosed
    ✓ price norms in the playbook section > are shown as figures with unit and region when the business uses industry ranges
    ✓ price norms in the playbook section > gives the guard exactly the figures the model was shown
    ✓ price norms in the playbook section > lets a reply quote a playbook range only when the settings allow it
   ```
5. **SSRF.** `packages/knowledge/src/crawl/safe-fetch.ts` (DECISIONS 114): http and https
   only, default ports only, no credentials in the URL; the name is resolved once, **every**
   address must be public (private, loopback, link-local, CGNAT, multicast, reserved, IPv4
   mapped, NAT64 and 6to4 forms of them are refused), and the socket is pinned to the address
   that was checked, so a second DNS answer cannot redirect it; every redirect is checked the
   same way (5 at most); size, time and content type are bounded; no HTTP proxy is used.
   110 tests, 5 of them over real sockets:
   ```
    66 isPublicAddress
    34 the guarded fetcher: what it refuses before connecting
     5 the guarded fetcher: names, addresses and redirects
     5 the guarded fetcher over real sockets
   ```
   Run from this VM earlier in the build: `live:crawl` refused `http://169.254.169.254/`,
   `http://localhost/`, `http://[::1]/` and `file:///etc/passwd` without connecting, and read
   `https://example.com` through the pinned socket.
   A fact from a website is kept only when the quote the model gives for it is on the page,
   it does not read like an instruction, and every dollar figure in it is on the page
   (DECISIONS 115); hidden elements are not read; robots.txt is honoured.
6. **json/jsonb (DECISIONS 59).** Every jsonb column is read and written through the Drizzle
   query builder. The only raw `execute(sql...)` calls in the package take advisory locks and
   read nothing. The jsonb merges of run statistics are asserted against real PostgreSQL.
